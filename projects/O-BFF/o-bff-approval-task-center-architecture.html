Approval Center / Task Center 架构图解

一句话：Approval Center 管“能不能执行”，Task Center 管“允许后怎么异步执行、切批、限流、记录结果”。

Markdown 版 治理中心深挖 项目索引

先分清职责

Approval

Approval Center

审批中心是后台高风险操作的状态机和审计层。

  • 谁提交
  • 谁审批
  • 是否通过
  • 审批历史
  • 通过后触发什么
Task

Task Center

任务中心是配置驱动的批处理执行引擎。

  • 解析文件
  • 分页/scroll 导出
  • 切批和限流
  • 调用下游 RPC
  • 生成结果和错误明细

协作链路

记忆主线 Admin 提交后先形成操作记录；高风险动作先审批；审批通过后才进入执行；执行成功失败由 Task Center 和下游返回决定。
Admin提交批量导入、导出、数据修复或高风险更新。
O-BFFInterceptor + Service + Manager 建立操作上下文。
Batch Operate记录这次批量操作，关联审批和结果。
Approval Center创建审批实例，推进节点，记录审批历史。
Operator Executer审批通过后衔接到执行链路。
Task Center切批、限流、调用下游、收集结果。
Owner ServiceProduct、Policy、Order、Marketing 等领域事实源。

Approval Center 内部模型

Definition

流程定义

定义业务如何审批、谁审批、节点怎么走。

Instance

审批实例

某一次真实提交，例如一次 CSV 导入或数据修复。

Node

审批节点

当前审批进度、审批人、通过或拒绝状态。

Mapping

业务映射

把 API / biz_type 映射到审批业务类型。

状态含义面试提醒
Pending等待审批。这时不能执行高风险动作。
Approved审批放行。只代表允许执行，不代表业务成功。
Rejected审批拒绝。停止后续执行，保留审计记录。
Executed后续执行完成。执行结果要看 Task/Event/Downstream。

Task Center 内部模型

Config

batch_task_config

定义 remote_type、字段映射、导入导出策略和额外配置。

Parser

文件 / 导出解析

导入解析 CSV，导出按 Page/Scroll 查询。

Splitter

切批

把大批量拆成小批次，降低单次请求压力。

RateConfig

限流熔断

控制 batch size、并发、QPS、timeout、circuit。

Executor

远程执行

调用下游 RPC、Assembly 或 JSON RPC。

Result

结果沉淀

成功数、失败数、错误明细、S3 文件、download record、monitor。

典型批量导入

1
Admin 上传 CSV

提交批量操作，O-BFF 校验文件和业务类型。

2
创建 Batch Record

记录这次操作，后续可查状态和下载结果。

3
Approval Center 审批

高风险操作先审批，拒绝则不执行。

4
Task Center 执行

解析文件、字段转换、切批、限流、调用下游。

5
结果文件

汇总成功失败、错误原因，上传 S3 并提供下载。

面试追问

不等于。审批通过只是风险控制层放行，实际业务执行还要看 Task Center、reliable event 或下游 RPC 的结果。
批量和长耗时任务不能同步卡住页面。Task Center 统一处理文件、切批、限流、下游调用、S3 和错误明细。
下游最好返回局部失败结构，Task Center 汇总成功数、失败数和单条错误，生成结果文件供 Admin 下载。
靠重复请求控制、batch/task record、业务唯一键和下游幂等一起防。不能只依赖前端按钮禁用。

1 分钟讲法

Approval Center 和 Task Center 是 O-BFF 后台治理的两个不同层次。Approval Center 负责高风险操作的审批状态机，解决“能不能执行、谁审批、怎么审计”；Task Center 负责审批通过后的异步批处理，解决“怎么解析文件、怎么切批、怎么限流、怎么调下游、怎么记录成功失败和错误明细”。审批通过不等于执行成功，这两个状态要分开看。
