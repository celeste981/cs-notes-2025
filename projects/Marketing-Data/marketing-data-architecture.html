Marketing-Data 架构图解

一句话：Marketing-Data 负责离线人群和数据预处理，把大查询、文件处理、batch history、Kafka 推送从 Marketing 主执行链路里拆出来。

Markdown 版 项目索引 Marketing Engine 面试专项

主链路

记忆主线 Marketing 主服务负责“什么时候、对谁、做什么动作”，Marketing-Data 专门负责“人群数据从哪里来、怎么批量抽、怎么推回 Marketing、怎么记录批次结果”。
Marketing Plan生成 plan_id、batch_id、data_source、group_condition、dest_topic。
Service 校验校验 plan、batch、topic、data source、condition、user group。
History 幂等batch_id 已存在直接返回；不存在先写 init history。
Async Handler根据 data_source 选择 ES/File/Hive/Insight handler。
Kafka Push过滤、去重、格式化 PlanRawMessage 后推目标 topic。
Result Monitor更新 success/failed、数量、耗时、错误详情和 Prometheus。

1 分钟讲法：Marketing-Data 是 Marketing 的离线数据抽取服务。它把 ES/S3/CSV/Hive/Insight 这些耗时、稳定、可重试的数据处理从 Marketing 主流程拆出来。入口校验 plan_id、batch_id、data_source 和 topic，Manager 用 batch_id 做幂等，先写 history，再异步选择 handler 拉数、过滤、去重、推 Kafka，最后更新执行结果和监控。

排障优先级
第一入口
定位 handler

producer/consumer/topic
消费和后续执行

面试排障可以按这个顺序讲：先查 batch，再查来源，再查推送，再查消费。

DataSource Handler

ES handler：解析 group_condition -> 转 DSL -> max length 检查 -> scroll 拉取 -> BloomFilter 去重 -> FormatOfflineRawResult -> PushWithTopic。
File handler：读取 S3/CSV -> mapping 转字段 -> 正则和日期过滤 -> append data -> BloomFilter 去重 -> 推 Kafka -> 记录文件路径。
pre-filter：source topic -> reliable consumer -> pre_filter_tab 规则缓存 -> RegexpMatch -> FillVariable -> 补 product_type/user_id -> dest topic。
排障从 batch_id 开始：查 history 状态和错误，再按 data_source 看 ES DSL/mapping、S3/CSV/Hive 文件、Kafka topic 或 Marketing 消费端。

优化项重点

Split

从 Marketing 拆出

离线数据抽取稳定但耗时，拆出后避免重试和大查询影响主执行链路。

Idempotent

batch_id 幂等

同一 batch 已存在 history 直接返回，配合唯一索引降低重复抽取风险。

History

先记账再异步

任务启动前写 init history，失败也有状态、错误详情和排障入口。

Handler

数据源插件化

ES/File/Hive/Insight 共用 Before/Process/After 生命周期，新增数据源不改主流程。

Query

查询保护

Admin 预览限制 size <= 100，ES scroll 用 maxLength、BloomFilter 和监控保护。

Prefilter

pre-filter 可切换

预过滤从 Marketing 迁出时保留配置开关，出现问题能回退旧链路。

风险点怎么回答
Kafka producer 失败代码里 producer 失败会记录日志和错误；面试可说需要结合 history、日志和消费端结果判断是否补偿，不能只看接口返回。
大人群抽取慢从 ES DSL、scroll batch、maxLength、去重、目标 topic 消费能力和 Prometheus 指标逐层排查。
文件数据异常看 S3/CSV 路径、字段 mapping、正则/日期过滤、错误详情和 batch history。
