# 三个月求职准备周计划：先稳后扩

> 适用前提：仍在全职工作，情绪和精力会波动；标准投入为每周 9-11 小时，最低可接受投入为 6-7 小时。  
> 目标不是三个月“学完后端和 AI”，而是形成足以投递两类岗位的可信能力组合：后端能讲清、项目能守住、Agent 有最小作品、简历能经受追问。
> 第 1 周从 **2026-08-10 至 2026-08-16** 开始；后续每周一开启一个新周期。

关联总纲：[career-transition-plan.md](../career-transition-plan.md)。

## 使用规则

### 每周固定时间盒

建议按以下节奏，避免工作日过度透支：

| 时段 | 时长 | 只做什么 |
| --- | ---: | --- |
| 工作日 3 晚 | 每晚 1-1.5 小时 | 一个明确主题：理解、写小例子、整理 1 分钟回答 |
| 工作日 2 个白天 | 每次 1 小时 | 轻量复习、错题、看已有项目代码；不安排硬题 |
| 周末半天 | 3-4 小时 | 项目深挖、系统设计、Agent MVP 或 Mock |
| 另一个短时段 | 1 小时 | 周复盘、算法 2 题、下周排程 |

至少保留 **1 个完整休息日** 与 **2 个不学习的晚上**。若一周只能投入 6-7 小时，**保留每周的“必须完成”项，删除算法、Agent 与所有可选项**；不能靠压缩睡眠补回来。

### 一项知识何时算完成

以下三项都完成，才算掌握到可面试；否则不要继续扩展新主题：

1. 能用 1 分钟中文解释它解决什么问题、核心原理和常见坑。
2. 能写出一个小例子、画出链路，或结合自己项目说明它在哪里出现。
3. 能回答至少两个追问，例如“为什么这样设计”“失败会怎样”。

### 每周产出上限

- 后端专题最多 2 个。
- 算法最多 2 题，以高频模板复盘为主。
- Agent 只在第 7 周开始；MVP 只做一个。
- 若当周加班或状态差，优先保住一次复盘和一个后端专题，允许其他项顺延。

## 12 周计划

| 周次 | 后端主线（必须完成） | 项目 / Agent | 求职动作 | 周末验收 |
| --- | --- | --- | --- | --- |
| W1 | Go：`slice/map/interface/defer/error`；每个主题形成 1 分钟回答 | 选一个现有真实项目，写“请求链路 + 我的职责”草稿 | 建立错题/弱项清单；算法 2 题 | 能不用资料解释 slice 扩容、map 并发风险、defer 执行顺序 |
| W2 | Go：`goroutine/channel/mutex/context`；补 `go test` 与 race detector 基础 | 为项目补 3 个并发/超时/重试场景 | 算法 2 题 | 能回答：何时用 channel，何时用 mutex；context 为什么不能滥用 |
| W3 | MySQL：索引、事务、MVCC/锁；Redis：缓存穿透/击穿/雪崩与一致性 | 将一个真实查询或缓存链路画成图 | 算法 2 题；开始收集深圳 JD 10 条 | 能讲一次慢查询/缓存风险的排查思路 |
| W4 | Kafka：消费语义、幂等、重试、DLQ；分布式：超时、重试、幂等 | 完成一个“消息/批任务可靠性”STAR 故事 | 算法 2 题；整理 JD 高频关键词 | 能讲清至少一次“重复消息怎么处理” |
| W5 | 系统设计：高并发后台/发券类任务的限流、异步、库存/预算一致性 | 选择最能守住的一个项目，准备 5 分钟版本 | Resume B 事实素材初稿 | 画出系统设计图，并说清 3 个取舍 |
| W6 | Go 综合复盘：HTTP/gRPC、连接/超时、pprof 基础；补最弱的一个后端专题 | 项目深挖与 1 分钟版本；不开发 Agent | Resume B 初稿；进行一次后端 Mock | 得到一张“后端 P0/P1 弱项清单” |
| W7 | Agent 基础：LLM API、Tool Calling、schema 校验、RAG 的来源与引用 | 开始 Agent MVP：两个只读 Tool + 本地知识样例 | Resume A 只写已完成事实；算法 2 题 | 可运行一次“检索 + 工具调用”演示 |
| W8 | Agent 工程：状态机、timeout、有限重试、幂等、trace | MVP 加 task state、失败处理、10-20 条评估样例 | Mock：项目 1 分钟讲解 | 可演示成功与失败各一个场景 |
| W9 | 系统设计复盘：可观测性、降级、容量与成本；补 Mock 暴露的后端弱项 | 冻结 Agent 新功能；补 README、测试、架构图、Demo | Resume A/B 定稿 v1；算法 2 题 | 无需打开代码也能讲清 Agent 的边界与未做项 |
| W10 | 高频后端题串讲：Go + DB + Cache + MQ + 分布式 | 只维护，不加功能 | 选 20-30 个目标 JD，逐条匹配；完成 2 次 Mock | 形成投递优先级和简历版本选择规则 |
| W11 | 根据 Mock / JD 的共性缺口，只补 1-2 个主题 | 项目只用于演示和回答 | 完成投递材料、准备自我介绍；开始小批量投递 | 能完成一轮 45 分钟模拟面试 |
| W12 | 只复习 P0 弱项和真实面试反馈 | 不开发新功能 | 稳定投递深圳岗位；每次面试后当天复盘 | 有可持续的“投递—面试—复盘”循环 |

## 前六周为什么暂不做 Agent

你当前的主风险是 Go / 后端基础“不敢说、不敢被追问”，不是缺少一个 Agent Demo。前六周先修复这个风险，收益同时覆盖两类岗位。Agent MVP 放到 W7-W8，只花两周，是为了增加差异化，而不是改变你的主身份。

## 精力不稳定时的三档执行法

| 状态 | 本周投入 | 只完成什么 | 不做什么 |
| --- | ---: | --- | --- |
| 正常周 | 9-11 小时 | 表格中的后端主线、一个项目产出、求职动作 | 不额外加新课程/新框架 |
| 忙碌周 | 6-7 小时 | 一个后端专题 + 一次项目回看 + 20 分钟复盘 | 算法、Agent、额外系统设计 |
| 低能量周 | 2-4 小时 | 看已有笔记并录一段 1 分钟口述；更新“不会的问题” | 不补进度、不自责、不做项目开发 |

低能量周不是计划失败。下周回到正常周即可，严禁用熬夜“补债”。

## 每周复盘模板（20 分钟）

```markdown
### 本周完成
- 后端：
- 项目：
- 求职：

### 我现在能讲清的 3 件事
1.
2.
3.

### 仍然会害怕 / 答不上来的问题
-

### 下周只保留的 3 件事
1.
2.
3.
```

“仍然会害怕”的问题不是失败清单，而是下一周唯一需要处理的输入。不要一次处理十个弱项。

## 触发收缩的信号

- 连续两周未完成计划的 60%：下一周删掉 Agent 和算法的可选项，只保留后端主线与复盘。
- W6 后仍不能讲清一个现有项目：W7 不启动 Agent，先用一周补项目表达；这比仓促做 Demo 更有价值。
- W8 后 MVP 仍不能演示：项目冻结在当前范围，整理已完成部分与技术反思，绝不临时增加功能。
- 收到面试：立即用其 JD 覆盖该周的可选项，但保留一次复盘。
