# MySQL 小白术语表


可视化页面：[glossary.html](glossary.html)
这份术语表先帮助建立直觉，不追求一次性讲完所有细节。后续每道题会再结合具体场景展开。

## 数据库基础

| 术语 | 小白解释 |
| --- | --- |
| 数据库 | 存数据的系统，可以理解成一个更强大的 Excel 文件集合。 |
| 表 | 一类数据的集合，比如用户表、订单表、保单表。 |
| 行 | 表里的一条记录，比如某一个用户。 |
| 列 | 表里的一个字段，比如用户 ID、姓名、手机号。 |
| SQL | 操作数据库的语言，比如查询、插入、更新、删除数据。 |
| 主键 | 一行数据的唯一 ID，常见是 `id`。 |

## 查询相关

| 术语 | 小白解释 |
| --- | --- |
| 索引 | 数据库里的目录。没有索引像从头翻整本书，有索引像先查目录。 |
| B+ 树 | MySQL 索引常用的数据结构，适合范围查询和排序。 |
| 回表 | 先通过二级索引找到主键，再回到主键索引里拿完整数据。 |
| 覆盖索引 | 查询需要的字段都在索引里，不用回表。 |
| 最左前缀 | 联合索引要从最左边的字段开始用，像查字典先按第一个字排序。 |
| 执行计划 | MySQL 打算怎么执行一条 SQL，比如用哪个索引、扫多少行。 |
| 优化器 | MySQL 里负责选择执行计划的组件。 |

## 架构相关

| 术语 | 小白解释 |
| --- | --- |
| Server 层 | MySQL 负责连接、解析 SQL、优化 SQL、调度执行的部分。 |
| 存储引擎 | 真正负责怎么存数据、怎么读数据的部分。常见是 InnoDB。 |
| InnoDB | MySQL 默认常用存储引擎，支持事务、行锁、MVCC、崩溃恢复。 |
| Buffer Pool | InnoDB 的内存缓存，把常用数据页放内存里，减少读磁盘。 |
| 连接池 | 服务提前维护一批数据库连接，避免每次查询都重新建连接。 |

## 事务和并发

| 术语 | 小白解释 |
| --- | --- |
| 事务 | 一组操作要么都成功，要么都失败，比如扣库存和创建订单要一起成功。 |
| ACID | 事务的四个特性：原子性、一致性、隔离性、持久性。 |
| 锁 | 防止多个事务同时改同一份数据导致混乱。 |
| 行锁 | 锁住某几行数据，而不是整张表。 |
| 间隙锁 | 锁住一个范围里的空隙，防止别人插入新数据。 |
| MVCC | 多版本并发控制，让读写尽量互不阻塞。 |
| Read View | 事务读数据时看到的一个快照视图。 |

## 日志和复制

| 术语 | 小白解释 |
| --- | --- |
| redo log | InnoDB 的崩溃恢复日志，保证提交后的数据不会因为宕机丢失。 |
| undo log | 回滚日志，也支持 MVCC 读取历史版本。 |
| binlog | MySQL Server 层日志，主要用于主从复制和数据恢复。 |
| 主从复制 | 主库写数据，从库复制主库的数据，常用于读写分离。 |
| 主从延迟 | 从库复制比主库慢，导致刚写入的数据在从库暂时查不到。 |

## 分库分表

| 术语 | 小白解释 |
| --- | --- |
| 分库分表 | 把数据按规则拆到多个库或多张表里，避免单库单表过大。 |
| 分片 | 被拆出来的一个库或一张表，可以理解成一个数据桶。 |
| 分片键 | 决定一条数据放到哪个分片的字段，比如 `policy_id`、`order_id`。 |
| 本地自增 ID | 每个库自己生成的自增主键，只保证当前库内唯一，不保证所有库全局唯一。 |
| 全局唯一 ID | 在所有库、所有分片里都唯一的 ID，适合做跨分片的数据身份标识。 |
| 倍数扩容 | 新分片数是旧分片数的整数倍，比如 `8 -> 16`、`8 -> 24`。 |
| 全量同步 | 把旧库已有历史数据整体同步到新库。 |
| 增量同步 | 全量同步期间业务还在写，用 binlog 把后续变化继续同步过去。 |
| 数据校验 | 对比新旧库数据是否一致，防止迁移后缺数据、重复数据或数据被覆盖。 |

## 排障相关

| 术语 | 小白解释 |
| --- | --- |
| 慢 SQL | 执行很慢的 SQL，可能因为没走索引、扫太多行、锁等待等。 |
| explain | 查看 SQL 执行计划的命令。 |
| 锁等待 | 一个事务持有锁没释放，其他事务只能等。 |
| 死锁 | 两个事务互相等对方释放锁，谁都走不下去。 |
