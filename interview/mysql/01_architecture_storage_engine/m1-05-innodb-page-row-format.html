行格式 你需要记住的点 面试说法
REDUNDANT 老格式，额外信息多。 了解历史兼容即可。
COMPACT 紧凑格式；大字段溢出时，本页可能留前 768B 加指针。 能说清一条记录内部结构。
DYNAMIC 大字段更彻底放到溢出页，本页通常只留 20B 指针。 MySQL 5.7.9+ 和 8.0 常见默认，更适合大字段表。
COMPRESSED 页压缩，节省空间和 I/O，但消耗 CPU。 线上使用要看压缩收益和 CPU 成本。

5. 面试时怎么讲

先讲短答，再根据追问展开。

1-2 分钟版本

InnoDB 默认按 16KB 的 Page 管理数据，表数据在聚簇索引 B+ 树里，叶子节点页就是数据页。一个数据页里不只有用户记录，还包括 File Header、Page Header、Infimum/Supremum 虚拟记录、User Records、Free Space、Page Directory 和 File Trailer。页内记录通过 next_record 按主键顺序形成链表，Page Directory 是稀疏目录，先二分定位分组，再在组内顺链表找。每页能存多少行取决于平均行大小，比如每行 100B 左右，16KB 页扣掉开销后大概能放 150 行。行格式方面，常见有 REDUNDANT、COMPACT、DYNAMIC、COMPRESSED，重点是 COMPACT 会在本页保留大字段前 768B 和指针，而 DYNAMIC 更倾向于本页只留 20B 指针，把完整大字段放到溢出页。

追问：为什么一行不能接近 16KB？

答：B+ 树页至少要能放两条记录，才能正常分裂和维护树结构。大字段会放到溢出页，不会都硬塞在当前页。

追问：varchar(255) 和 varchar(256) 差异？

答：看最大字节数。最大不超过 255 字节，长度可用 1 字节；超过通常要 2 字节。注意 utf8mb4 下 255 个字符可能是 1020 字节。

追问：为什么不每条记录一个目录槽？

答：太浪费。Page Directory 是页内稀疏索引，先缩小到一组记录，再组内扫描，空间和性能更平衡。
