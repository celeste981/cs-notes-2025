Buffer Pool 的工作原理与改进 LRU

读写路径 改进 LRU 三类链表 面试说法

先抓住一句话

Buffer Pool 是 InnoDB 的数据页缓存。读数据先找内存，写数据也先改内存页，页变成脏页后再异步刷盘。改进 LRU 的目的，是防止全表扫描、预读页这类一次性冷数据把热点页挤出去。

缓存单位

Page，不是单行。

写入方式

先改内存，后刷磁盘。

LRU 改进

new page 先进入 old 区。

为什么普通 LRU 不够

普通 LRU 会把刚访问的页放到最热位置。全表扫描时，大量只访问一次的历史页也会被当成热点，真正频繁访问的订单、用户、保单页反而被淘汰，这就是缓冲池污染。

2. 改进 LRU 怎么保护热点页

young 区：真正热点

最近且多次访问的页更容易留在这里。

old 区：新页和冷页

新读入页先放这里，避免直接污染热点区。

默认 old 区约 3/8，young 区约 5/8。新页插入 old 区头部，也就是 midpoint 附近。

场景：正常热点查询

3. Buffer Pool 里的三类链表

Free List

管理空闲页框。新 Page 读入时，优先从这里拿位置。

LRU List

管理已缓存页的冷热，决定哪些页更该留下，哪些页可以淘汰。

Flush List

管理脏页。后台刷盘和 checkpoint 会关注这里。

现象 原因 处理方向
全表扫描后核心接口变慢 冷页进入缓存，热点页被淘汰。 优化 SQL 和索引，减少大扫描。
重启后短时间查询慢 Buffer Pool 冷启动。 配置 Buffer Pool dump/load 预热。
脏页刷盘压力大 写入多，Flush List 积压。 看 redo、checkpoint、磁盘 I/O 和刷盘参数。

4. 面试 1 分钟说法

Buffer Pool 是 InnoDB 的内存缓存，主要缓存数据页和索引页。InnoDB 按 Page 管理数据，默认 16KB，所以查询一行时通常会把整页读入 Buffer Pool。读数据先看 Buffer Pool，命中就直接读内存；未命中才读磁盘。更新也先改 Buffer Pool 中的数据页，页变成脏页后由后台线程异步刷盘。InnoDB 不用简单 LRU，是因为数据库里有预读和全表扫描，大量只访问一次的冷页会污染缓存。改进 LRU 把链表分成 young 区和 old 区，新读入页先进入 old 区，只有在 old 区停留超过 innodb_old_blocks_time 后又被访问，才晋升到 young 区。这样热点页更容易留在内存里。
