M1-01 MySQL 查询流程

一句话定位

一条 SELECT 不是直接去磁盘拿数据，而是先走 Server 层的连接、解析、优化、执行，再由 InnoDB 负责真正的数据读取。

类比记忆

像去仓库取货：门卫验身份，前台听懂需求，调度员选最短路线，执行员去拿货，仓库管理员真正找到货。

记忆口诀

连、查缓、析、优、执、引擎、返回。MySQL 8.0 之后“查缓”基本从主流程里删除。

答题骨架

Server 层管 SQL 流程；InnoDB 层管数据页、索引、Buffer Pool 和事务能力。

点击式流程拆解

第 1 步

客户端连接

客户端通过 TCP 连接 MySQL，连接器认证账号并读取权限。

为什么要记：权限通常在连接建立时读取，修改权限后旧连接不一定立刻感知。

第 2 步

查询缓存

MySQL 8.0 前可能检查查询缓存，8.0 已删除。

为什么要记：面试要主动说“老版本有，8.0 删除”，体现版本意识。

第 3 步

分析器

做词法和语法分析，把 SQL 解析成 MySQL 能理解的结构。

为什么要记：语法错误通常在这一阶段暴露。

第 4 步

优化器

基于成本选择索引、Join 顺序和执行计划。

为什么要记：不是你写了哪个索引就一定用哪个，优化器会估算成本。

第 5 步

执行器

检查权限，按执行计划调用存储引擎接口。

为什么要记：执行器自己不管理数据页，它通过引擎接口拿记录。

第 6 步

InnoDB

通过 B+ 树索引定位页，优先从 Buffer Pool 读，必要时读磁盘。

为什么要记：InnoDB 才是数据页、索引、事务、锁的核心。

第 7 步

返回结果

执行器过滤和组装结果集，返回给客户端。

为什么要记：WHERE 条件和引擎下推要区分，别把所有过滤都说成 Server 层完成。

对比记忆

Server 层连接、解析、优化、执行调度、权限检查、binlog。回答 SQL 通用流程。
InnoDB 层Buffer Pool、B+ 树、数据页、事务、锁、redo/undo。回答数据怎么存、怎么读。
查询缓存8.0 删除，老版本才可能命中。别把它当现代 MySQL 必经步骤。

先记住这几个抓手

  • Server 层：连接、解析、优化、执行调度、权限检查、binlog。
  • InnoDB 层：Buffer Pool、B+ 树、数据页、事务、锁、redo/undo。
  • 查询缓存：8.0 删除，老版本才可能命中。

容易说错

  • 把优化器和执行器职责混在一起。
  • 说 SELECT 一定不经过 InnoDB。
  • 忘记 MySQL 8.0 删除查询缓存。
  • 只背流程，不会说 Server 层和 InnoDB 层边界。

3 个自测问题

选择索引、Join 顺序和执行计划。

执行器调用接口，InnoDB 真正管理和读取数据页。

要讲版本差异：8.0 已删除，老版本才有。

面试口述

30 秒短答：一条查询进入 MySQL 后，先由连接器建立连接、认证并读取权限。

一条查询进入 MySQL 后，先由连接器建立连接、认证并读取权限。MySQL 8.0 之前可能检查查询缓存，但 8.0 已经删除。然后分析器做词法语法分析，优化器选择索引和执行计划，执行器检查权限并按计划调用存储引擎。真正的数据页和索引由 InnoDB 管理，InnoDB 会优先从 Buffer Pool 读取，不在内存再读磁盘。总结就是 Server 层负责 SQL 通用流程，InnoDB 负责数据存取。
