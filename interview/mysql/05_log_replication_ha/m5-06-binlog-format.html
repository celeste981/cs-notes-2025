Statement 记 SQL，Row 记行变更，Mixed 自动选择。

类比记忆

记忆口诀

Row 更稳，日志更大；MINIMAL 来减肥。

答题骨架

Statement / Row / Mixed 的一致性和体积取舍。

看图记 3 句话

  • 生产更常推荐 Row，尤其是复制一致性优先时。
  • Row 日志大可以结合 binlog_row_image=MINIMAL 缓解。
  • Statement 的风险来自非确定性 SQL 和环境差异。

点击式流程拆解

第 1 步

Statement

记录原始 SQL。

为什么要记：日志小但可能不确定。

第 2 步

Row

记录每行变化。

为什么要记：一致性最好但体积大。

第 3 步

Mixed

MySQL 自动选择。

为什么要记：行为不如 Row 透明。

第 4 步

row_image

控制 Row 记录哪些列。

为什么要记：MINIMAL 可减小体积。

第 5 步

生产选择

主从和恢复优先 Row。

为什么要记：确定性更重要。

对比记忆

Statement小，但 UUID/RAND 等可能不一致。旧系统或简单场景。
Row准，但批量更新大。生产主从推荐。
Mixed折中。可预期性弱。

先记住这几个抓手

  • Statement：小，但 UUID/RAND 等可能不一致。
  • Row：准，但批量更新大。
  • Mixed：折中。

容易说错

  • 说 Row 没有代价。
  • 不知道 binlog_row_image。
  • 把 binlog 格式和 redo 混淆。

3 个自测问题

不确定函数或环境差异会导致主从不同。

binlog 暴增和主从延迟。

减少 Row 记录列数。

面试口述

30 秒短答：Statement 记录 SQL，日志小但可能不一致；Row 记录每行变更，一致性最好但日志大；Mixed 自动选择。

Statement 记录 SQL，日志小但可能不一致；Row 记录每行变更，一致性最好但日志大；Mixed 自动选择。生产通常选 Row，必要时用 binlog_row_image=MINIMAL 控制体积。
