看图记 3 句话

  • 不要说成普通文档库，要突出 Agent 可用、可信、可治理。
  • 面试中可以按“来源 -> 服务 -> Agent -> 反馈”讲。
  • 涉及业务准确率、覆盖率等指标，缺失时标记待补充。

点击式流程拆解

第 1 步

资料分散

代码、Confluence、PRD、TD、交付证据分散。

为什么要记：Agent 容易缺上下文。

第 2 步

知识分层

Project KB、Domain KB、Overall KB。

为什么要记：避免知识混杂。

第 3 步

Knowledge Service

索引、metadata、source、owner、权限。

为什么要记：不是复制大文档。

第 4 步

Agent 使用

需求分析、TD、代码生成、Review。

为什么要记：按场景检索。

第 5 步

反馈闭环

查不到、查错、过期进入修复。

为什么要记：知识持续维护。

对比记忆

普通文档库存文档，主要给人看。缺少 Agent 使用治理。
Agent 知识底座带来源、owner、权限和检索质量。给 Agent 受控使用。

先记住这几个抓手

  • 普通文档库：存文档，主要给人看。
  • Agent 知识底座：带来源、owner、权限和检索质量。

容易说错

  • 包装成已上线平台。
  • 编造准确率指标。
  • 不说明个人贡献待补充。

3 个自测问题

Knowledge Service 提供受控检索源。

source、owner、更新时间和反馈闭环。
